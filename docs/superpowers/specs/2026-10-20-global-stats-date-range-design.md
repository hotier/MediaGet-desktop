# 统计页全局日期范围与统一 SQLite 存储设计

## 状态

设计草案，待业主审阅。业主已确认：统计事件与作品历史均需留存完整明细，不设条数或时间上限；所有结构化本地业务数据统一迁入 SQLite；系统诊断日志与媒体/缓存文件继续留在文件系统。

## 目标

- 页面顶部用一个日期范围选择器替代刷新按钮，支持近 7 / 30 / 90 / 365 天和自定义开始、结束日期。
- 同一范围统一控制指标卡、趋势、平台解析/下载、资源类型、作者解析/下载、按日热力图。
- 每次统计事件都有结构化明细，永久保留；不得用聚合计数或诊断日志替代事件明细。
- 作品解析历史永久保留，移除现有 5000 条持久化上限；页面按页加载，单次 IPC 不搬运全库。
- 所有结构化本地业务数据以一个 SQLite 数据库为真源：设置、内核配置（含用户自配 Cookie）、下载队列、作品历史、统计事件及迁移元数据。
- 下载队列任务与作品历史、统计事件一样不设条数或时间上限；下载页按页查询终态记录，避免把完整队列载入内存。
- 下载媒体文件、临时缓存/断点文件、轮转诊断日志继续留在文件系统；数据库只记录必要的路径和业务状态。
- 日期按本机自然日解释，起止日均包含；未来日期不可选，开始日不能晚于结束日。

## 方案选择

1. **继续 JSON，追加无限事件数组**：不引入数据库，但写入/筛选需要重写或扫描不断增长的文件，删除、分页和崩溃恢复成本持续上升。拒绝。
2. **统一本地 SQLite（采用）**：结构化业务数据按行写入，索引支持日期、平台和作品查询；事务保证跨表写入一致，支持无界持久化与分页。迁移和打包/运行时适配需要一次架构改造。
3. **SQLite 加独立汇总快照**：查询更快，但产生第二份统计真源与重建/一致性复杂度。首版先用索引明细查询并聚合，性能数据证明不足后再加可重建缓存。

## 数据模型与边界

数据库放在 Electron `userData`，由主进程唯一管理，按版本迁移。表建议如下：

- `app_settings`：保存 `AppSettings`。设置更新按事务提交。
- `kernel_config`：保存内核配置键及用户自配 Cookie。Cookie 仍只由主进程读取，renderer 只能经已有 IPC 白名单使用获准操作。
- `queue_tasks`：保存所有队列任务快照和终态，不设条数或时间上限；进度更新按现有节流策略批量 upsert，保留任务状态、失败原因和必要文件路径。活动任务在内存实时更新，终态任务由数据库分页查询。
- `history_entries`：保存现有 `HistoryEntry` 作品/下载明细，不再截断旧行；保留当前作品键、upsert、删除语义。历史页改为主进程分页，筛选/排序在数据库执行。
- `stats_events`：不可变追加每次统计事件，字段包括事件 ID、事件种类、事件时刻、归一平台键、资源类型、结果、字节数、传输时长及可空的作品引用。至少覆盖解析成功/失败、下载成功/失败/取消；每次解析请求单独一行，同作品重复解析也不合并；每个下载任务终态一行。
- `schema_migrations`：记录已成功应用的 schema 迁移版本。

事件表只存统计所需字段，不写 URL、Cookie、文件名、作者名或媒体内容。成功解析/下载事件通过作品引用关联作品历史；作者维度按所选日期内的作品键去重，作者名从历史读取。解析失败或缺少作品引用时仍计入总量和平台，但不虚构作者归属。用户主动删除作品历史后，对应统计事件保留、作品引用置空，日期总量不因删除历史而改变。

索引至少覆盖事件时刻、事件种类 + 时刻、平台 + 时刻、资源类型 + 时刻、作品引用 + 时刻；历史表覆盖作品键、平台 + 创建时间、创建时间。日期热力和其他统计均从相同范围内的事件聚合，避免统计区块口径分叉。SQL 必须参数化，renderer 不接收全量事件列表或原始 SQL。

SQLite 驱动需在实施计划阶段按当前 Electron/Node 运行时和 Windows 打包约束确认；优先使用随 Electron 运行时可用的能力，只有不满足稳定性要求时才引入需原生重建的依赖。启用事务与 WAL；相关事件和历史 upsert 同一事务写入。进程退出时先 flush 队列，再关闭数据库并完成 checkpoint。

Cookie 迁入 SQLite **不代表静态加密**：仍受 Electron 主进程边界与当前 `userData` 本机文件权限保护；日志、错误与统计查询不得输出 Cookie。磁盘加密需另做密钥来源与恢复设计，不在本次增加自制加密。

## 日期范围与统计口径

- 范围边界按本机自然日转换；SQL 使用 `startAt <= eventAt < dayAfterEnd`，避免毫秒边界漏数。
- 默认近 30 天。预设档为近 7 / 30 / 90 / 365 天；自定义日历区间选择开始日和结束日，应用后一次性更新全页，取消不改变当前已应用范围。
- 主进程提供按范围查询，renderer 不读全量事件。`stats:get` 改为接受日期范围或新增 `stats:query` 时，按 AGENTS.md 同步 IPC 六件套并升 `CONTRACT_VERSION`。
- 指标卡、总体趋势、平台解析/下载、资源类型、作者维度、每日热力统一使用同一日期范围；趋势图不再单独维护日期选择器。其他指标切换保留。
- 下载成功率分母为所选范围内成功 + 失败；取消独立统计、不进入成功率分母。解析成功率按解析成功 + 失败计算。作者解析作品按作品键去重，重复解析请求仍各计一次请求。
- 下载任务数按统计事件计数；资源文件数与体积按现有历史 `files` 字段口径展示。平台/资源类型均由事件字段聚合。
- 事件级日期统计从迁移后真实记录的首个事件时刻开始完整可查；范围跨过该时刻时标明可用数据起点。旧累计数不得混进范围值，造成看似精确的历史日期结果。

## 旧数据迁移

- 首次启动创建数据库，把 `config.json` 的 settings/kernel、`queue.json` 任务、`history.json` 全部可读行和 `stats.json` 累计档导入目标表/迁移基线；每份源文件的迁移状态写入迁移账本。
- 迁移必须可中断恢复、幂等：数据库提交并校验行数/关键总量后才归档旧 JSON；成功前不删除或覆盖源文件。Cookie 逐键校验，但绝不进入日志、错误通知或终端输出。
- 旧统计档含生命周期累计桶和有限的总体按日桶，不能还原每次解析、失败/取消时刻或完整平台/类型日维度；不可伪造旧事件，也不能把累计数均摊到日期。迁移前累计值可作为独立的“迁移前累计”保存/展示，不并入可筛选事件数据。
- 旧 `history.json` 只能迁移当前文件中仍存在的记录；过去被 5000 条上限淘汰的明细已不可恢复。移除上限保证升级后新增记录不再因数量淘汰。
- 迁移成功后旧 JSON 作为短期恢复备份保留；备份具体保留期由实施计划根据恢复流程确定，之后数据库是唯一读写真源。数据库打不开或迁移失败时不得静默初始化空库覆盖旧文件，应报告错误并提供恢复路径。
- 队列迁移保留源 JSON 中全部现存任务及终态恢复语义；设置/Cookie 保留既有业务值和主进程访问边界。升级前已被 200 条上限淘汰的队列任务同样不可恢复。

## UI、历史分页与性能

- 顶部日期选择器替代刷新按钮；失败态保留重试。正常刷新沿用当前日期范围，不增加第二套日期控件。
- 范围标签只在顶部显示；局部图表沿用现有空态。范围包含迁移前日期时显示统计数据覆盖起点。
- 历史查询使用主进程 limit + cursor/offset 分页。跨页筛选和删除覆盖数据库全部匹配历史；显式“选择全部筛选结果”不通过单个 IPC 传全库 keys。
- 本机不按条数/时间自动删除作品历史、统计事件或队列任务。设置体量小；数据库随长期使用增长，历史/终态队列查询必须走索引与分页，不整库读入主进程/renderer。活动队列仅将未完成任务保留在 downloader 内存，终态任务由 SQLite 提供分页；首版不设自动清理。
- 数据库备份/导入/导出不得把 Cookie 原样放进普通诊断导出；下载文件、缓存和轮转日志不迁入数据库。

## 验收重点

- 重复解析、解析失败、下载完成、失败、取消事件可按天/平台/类型精确聚合。
- 跨午夜、本机日边界、自定义单日区间与空范围边界正确。
- 设置/Cookie、队列、5000 条旧历史和旧累计统计迁移后不丢不重；中断重跑幂等；源文件保留至数据库验证成功。
- 超过 5000 条后仍能分页查看最旧历史，跨页筛选/删除不突破 IPC 载荷上限。
- 成功解析/下载等按业务规则有关联历史的事件与历史写入保持事务一致；解析失败、mock 解析等本来没有历史的事件可独立存在。事务失败与重启后不能留下半写入的关联数据。
- Cookie 不出现在 renderer、日志和错误输出；数据库打开/迁移失败不会覆盖源 JSON。
