## 1. 与当前 goal 的合并策略

设计方案的分阶段路线与现有 goal **不冲突、可穿插**，合并规则如下：

| 事项 | 时机 | 理由 |
| --- | --- | --- |

## 2. 铁律（违反任何一条 = 打回）

1. **依赖不设禁令**（2026-10-14 业主第三次修订 C4，见蓝图 C4 与本文件铁律 1 全文）：组件库 / 样式范式 / 动画库 / 路由**按需引入，不再审查资格**——shadcn/ui、Tailwind utility、framer-motion、tanstack 全部解禁；此前两轮修订的 headless 白名单作废。剩下的只是工程纪律：新增 runtime 依赖与 lockfile **同 commit** 提交并跑 §2 铁律 5 验收门；CSP `default-src 'self'` 仍禁远程字体 / icon font / 外链 SVG（C1，技术边界，与选库无关）。**原「引入 shadcn 前必须先处置 `tests/style-discipline.test.ts`」的前置已解除**：业主同日指令「都放宽，按照 Motrix 的 UI 设计框架和理念，不要给自己设限」，该测试现只剩三条与选库无关的工程断言（色值单一真源 / 变量必须声明 / 无 `--air-` 残留），玻璃、多高程、hover 位移与缩放动效不再受断言约束。**shadcn/ui 已按蓝图 §8 落地**（`components.json` + `renderer/src/components/ui/` + `@theme inline` 语义桥），后续加组件优先复用该 kit，不在 `styles.css` 里再写组件层。
2. **只加不改**：`downloader.ts` / `engine.ts` / `fallback.ts` / `core-adapter/*` 的逻辑一律不动；新数据只加**可选字段**或**新 channel**，`DEFAULT_SETTINGS` 兜底旧档。
3. **选择器名不再是约束**（2026-10-14 修订）：原条文要求 `.page / .card / .chip / .table / .field` 原地换 Token、不重命名，那是为「单文件 CSS 上做加法」压 diff 的前置。shadcn + Tailwind 迁移以组件为单位自带样式，`styles.css` 组件层随迁移收缩，**该前置撤销**。仍然有效的是：纯函数与契约层不因 UI 迁移而改动；`tests/*.test.ts` 里对界面文案/结构的断言要跟着迁移更新。
4. **契约变更照抄清单**（2026-10-14 单一真源改造后）：`types/ipc-contract.ts`(schema + `CONTRACT`/`EVENTS` 登记) → `types/ipc.ts`(channel 常量，形状自动派生) → `main/ipc.ts`(handler) → `preload/index.ts` → `renderer/lib/bridge.ts` → 测试，一个不落（蓝图 §4.2）。`tests/contract.test.ts` 会当场抓出漏登记与出参漂移。三个已验证的坑：`SettingsPatchSchema.strict()` 拒未知键；`settings:set` 传全量；Cookie 掩码 `"***"`=不改、`""`=清除。
5. **每阶段验收门**：`npm run typecheck && npm run lint && npm run test`（含 `boundaries.test.ts` 铁律 1：renderer 不得 import `@/lib`）。P5 附加核心验收：下载中点 ✕ → 进程存活、任务继续、托盘恢复后队列与 `.part` 完好。
