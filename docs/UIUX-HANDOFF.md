## 1. 与当前 goal 的合并策略

设计方案的分阶段路线与现有 goal **不冲突、可穿插**，合并规则如下：

| 事项 | 时机 | 理由 |
| --- | --- | --- |
| 更新横幅文案修正 | **立即**（在任何阶段之前） | 现状文案"重启应用即自动更新"与实际不符：`electron/main/index.ts` 只监听 `update-available`，从未监听 `update-downloaded`、未调 `quitAndInstall`。先把横幅改为「发现新版本，去设置检查并安装」，完整更新 UI 归 P6 |
| P0 Token 基座 + P1 组件层修补 | 阻断缺陷（CI ffmpeg URL / manifest 校验 / dev:electron 沙箱 / storeDir）修完之后、里程碑大功能之前做 | P0 只动 `renderer/src/styles.css` 一个文件、零契约；越晚做，后面新页面越要按旧样式返工 |
| P3 下载页重构 | **与 goal 里的"下载管理器与批量图集"合并为同一件事** | 契约字段 `groupId` 已存在（数据在 `DownloadTaskView.groupId`），批量图集的 UI 形态就是 P3 的"按组聚合 + 折叠"；分开做必然返工 |
| P4 结果卡补全（画质选择器等） | 里程碑 P2/P3 功能验收后 | 全部是"契约里已有、渲染层漏读"（`ParseData.qualities` / `platforms[].name` / `meta` 元数据），零 IPC 变更 |
| P2 明暗主题 | 小契约（`AppSettings.theme?` 可选字段 + zod + `nativeTheme`），随时可做 | 注意 `SettingsPatchSchema` 是 `.strict()`，先加 schema 再发字段 |
| P5 托盘 + 关窗最小化 | **优先级高于 README P4 自动更新完善** | 现状 Windows 上 `window-all-closed` 直接 `app.quit()`，下载中关窗=杀死全部任务，是用户可感知的最高伤害项；Tray/globalShortcut 全仓零命中 |
| P6 各项 | 逐个评估，按需 | 每项契约成本（4 处联动 + zod + 测试）已在蓝图 §4.1 表格标注 |

## 2. 铁律（违反任何一条 = 打回）

1. **依赖不设禁令**（2026-10-14 业主第三次修订 C4，见 README「关键设计决策」与蓝图 C4）：组件库 / 样式范式 / 动画库 / 路由**按需引入，不再审查资格**——shadcn/ui、Tailwind utility、framer-motion、tanstack 全部解禁；此前两轮修订的 headless 白名单作废。剩下的只是工程纪律：新增 runtime 依赖与 lockfile **同 commit** 提交并跑 §2 铁律 5 验收门；CSP `default-src 'self'` 仍禁远程字体 / icon font / 外链 SVG（C1，技术边界，与选库无关）。**原「引入 shadcn 前必须先处置 `tests/style-discipline.test.ts`」的前置已解除**：业主同日指令「都放宽，按照 Motrix 的 UI 设计框架和理念，不要给自己设限」，该测试现只剩三条与选库无关的工程断言（色值单一真源 / 变量必须声明 / 无 `--air-` 残留），玻璃、多高程、hover 位移与缩放动效不再受断言约束。**shadcn/ui 已按蓝图 §8 落地**（`components.json` + `renderer/src/components/ui/` + `@theme inline` 语义桥），后续加组件优先复用该 kit，不在 `styles.css` 里再写组件层。
2. **只加不改**：`downloader.ts` / `engine.ts` / `fallback.ts` / `core-adapter/*` 的逻辑一律不动；新数据只加**可选字段**或**新 channel**，`DEFAULT_SETTINGS` 兜底旧档。
3. **选择器名不再是约束**（2026-10-14 修订）：原条文要求 `.page / .card / .chip / .table / .field` 原地换 Token、不重命名，那是为「单文件 CSS 上做加法」压 diff 的前置。shadcn + Tailwind 迁移以组件为单位自带样式，`styles.css` 组件层随迁移收缩，**该前置撤销**。仍然有效的是：纯函数与契约层不因 UI 迁移而改动；`tests/*.test.ts` 里对界面文案/结构的断言要跟着迁移更新。
4. **契约变更照抄清单**（2026-10-14 单一真源改造后）：`types/ipc-contract.ts`(schema + `CONTRACT`/`EVENTS` 登记) → `types/ipc.ts`(channel 常量，形状自动派生) → `main/ipc.ts`(handler) → `preload/index.ts` → `renderer/lib/bridge.ts` → 测试，一个不落（蓝图 §4.2）。`tests/contract.test.ts` 会当场抓出漏登记与出参漂移。三个已验证的坑：`SettingsPatchSchema.strict()` 拒未知键；`settings:set` 传全量；Cookie 掩码 `"***"`=不改、`""`=清除。
5. **每阶段验收门**：`npm run typecheck && npm run lint && npm run test`（含 `boundaries.test.ts` 铁律 1：renderer 不得 import `@/lib`）。P5 附加核心验收：下载中点 ✕ → 进程存活、任务继续、托盘恢复后队列与 `.part` 完好。
