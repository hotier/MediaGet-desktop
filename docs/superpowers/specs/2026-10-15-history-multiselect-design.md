日期：2026-10-15　状态：业主已认可；10-17 四次修订（勾选框列与「重新解析」回归、动作条改浮窗、行内框改按需显形 + 间距收窄、表头框同规则不常驻，见「明确不做」那节与 §4A）

## 目标

历史页列表当前只能逐行操作（点行开详情）或整体「清空历史」（**修订 10-17**：那颗按钮连同 `history:clear` 通道已撤除，全清改走本页多选 = 表头全选 → 移除记录）。多选补上中间缺口：
挑出若干条，**删除**它们（不全清）或**复制/导出**它们的作品信息。

## 1. 选择模型

- **行键 = `groupId ?? id`**：一行可能聚了图集多文件，选中＝选中整组（一个 groupId）。
- **点行（无修饰）**：照旧打开底部详情 Sheet，行为不变。
- **Ctrl / ⌘ + 点**：切换该行选中态，且**不**开详情。
- **Shift + 点**：从「上一个被点的锚点」到当前行，按**当前可见行序**连续选中（范围含端点）。锚点取最近一次非-Shift 点选的行。
- **Ctrl / ⌘ + A**：**替换**当前选择为「可见全部行」（不是并入已有选择）。理由：全选是「我就要操作这些可见的」，若并入会把此前选中、但已被筛掉的行一起带进操作——与"我看到的=我要操作的"直觉相反。已筛掉的行仍可被删除/导出，但需经 Shift 范围或此前手动选中，不由 Ctrl+A 带入。
- **Esc**：浮层开着时归浮层（Radix 自收，选择不动）；没有浮层且有选中才清空选择。判据读 `data-state="open"`——Presence 退场中节点还挂在 DOM 上，只查存在性会把「刚收起浮层就按 Esc」吞掉。
- **勾选框那一列（10-17 加）**：点框只切换选中并 `stopPropagation`，不顺手把详情浮层弹出来——勾选是要动作条，不是要看这一行。
- **表头全选框（10-17 加）**：就是 Ctrl+A / Esc 的鼠标版——勾上＝**替换**为可见全部行，取消＝清空。三态判据只看可见行：一条没选=空、部分=`indeterminate`、全选=勾。两个坑：
  1. 部分态绝不能画成勾，否则下一次点击变成「清空」，用户以为刚才全选过；
  2. `onCheckedChange` 回调送来的值在 indeterminate 下是 `true`（Radix 按 非勾→勾 循环），照值走就会把「全选」做成「清空」——判据要读**当前**三态。
- **筛选时选择保留**：选中后再筛掉某行，该行仍在选择集合内（与 Windows 资源管理器一致）。动作条计数「已选 N 项」按选择集合大小，不按可见数。
- **视觉**：选中行**只上底色**（`bg-primary/15`），不新增样式体系。**修订 2026-10-17**：原写作「底色 + 整行描边」，业主令「选中的时候，那条记录不要有边框线条」后描边撤掉——整行已经跟着底色走，再框一道是把一行切成格子。仍保留描边的只有队列页跳转定位那一下的闪烁（1.8 秒即退，指认「这一行在这儿」，不是选择态）。**同日再修**：「选中是蓝、hover 是浅灰，两个底色会冲突」——带主色底的行把 hover 换成同色系加深一档（`hover:bg-primary/25`），未选中行保持灰 hover；口径与「为什么不靠 class 书写顺序」在 UIUX-DESIGN §2.3。**同日三修**：那层蓝底铺到卡片内缘时是**方角**，会顶穿表格卡的 12px 圆角（hover 灰同理）——裁在卡片自己身上（`overflow-hidden`），规则与「为什么不给表格容器补圆角」在 §1.5.2。

## 2. 动作条 · 窗口底部浮窗（10-17 改）

- **不占位**（业主指令 2026-10-17「多选操作栏不要占位，以浮窗的形式展示在窗口底部」）：工具栏不进选择态，浮窗浮在窗口底部。工具栏右侧也不再有按钮——**同日追加**：「清空历史」连同 `history:clear` 整条通道撤除（契约 v9），整表清空 = 表头全选 → 移除记录，走同一条 `history:remove`。此前两版（10-15「有选中=替换清空历史」、10-17 上午「清空历史常驻不动」）一并作废。
- 浮窗内容：~~`已选 N 项 · [复制] [导出 txt] [导出 CSV] [重新解析] [移除记录] · [取消选择]`~~ → **`已选 N 项 · [导出] [重新解析] [移除记录] · [取消选择]`**（业主指令 2026-10-17「移除多选菜单的复制按钮，导出按钮合并成一个导出，点击导出后弹窗选格式」；见 §4）。
- **一次只放一层**：底部那条带已有「作品信息」浮层占着，浮窗在它开着时**让位**——只让可见性，选择集合不动；收起浮层浮窗自己回来。（原记的副作用「两枚 destructive 入口并存」随清空历史撤除而不存在，本页只剩「移除记录」一枚。）
- 实现要点（踩过的）：`fixed` 必须 **portal 到 `body`**，否则 `main` 的 page-enter 动画（transform + filter）成为 containing block，坐标缩到内容区（实测中心偏 92px）；居中参照系与对话框一致（功能区中心，不含侧栏）；表格尾部垫一块 `ResizeObserver` 量来的等高空隙，否则滚到底时最后一行连勾选框都被压住。
- 按钮一律写它**做的事**：这条只撤台账那一行、磁盘上的文件不动，所以它不叫「删除」。

## 3. 动作 A · 移除记录选中（唯一动主进程的）

- 主进程新增 `store.removeHistory(ids)`：按**条目 id** 过滤后落盘，**返回剩余列表**（UI 直接 `setList(剩余)`，省一次回读）。
  - 传入的是行键集合（`groupId ?? id`）；主进程删除口径：命中「条目 id ∈ ids **或** `条目.groupId ∈ ids`」的全部记录——保证删整组。
- 契约新增通道 `history:remove { ids: string[] } → HistoryEntry[]`，在 `types/ipc-contract.ts` 的 `CONTRACT` 登记，`types/ipc.ts` 出 `IPC.historyRemove` 常量与派生类型；`contract.test.ts` 自动对账（漏登记即红）。
- 删除后清空选择集合，动作条收回。
- **只删记录，绝不碰磁盘文件**（历史本就只存路径字符串，不存内容）。整表清空也走这条：`keys` 上限 5000 = `HISTORY_MAX`，一次点得掉整张表，所以不再需要 `history:clear`。
- 二次确认：弹 Dialog（destructive）；确认后执行。（原写作「复用现有『清空历史』确认弹窗的形制」——那颗按钮 10-17 撤除后，这枚就是本页唯一的 destructive 确认。）

## 4. 动作 C · 导出（零 IPC，纯前端；10-17 改为「一枚导出 + 格式弹窗」，复制撤除）

- 每条选中行复用 `buildWorkInfoText`（renderer/src/lib/work-info.ts）生成正文。
- 多条拼接：以一行分隔 `———`（全角破折号成串，可读、不与正文里的破折号项混淆）连接各条。
- ~~**复制**：整段进 `navigator.clipboard.writeText`，成功 toast「已复制 N 条」，失败 toast「复制失败」~~ → **批量复制整枚撤掉**（业主指令 2026-10-17「移除多选菜单的复制按钮」）。**撤的是批量档，不是能力**：单行「复制作品信息」仍跟着作品走，在「作品信息」浮层的标题行里，那条链路与 `buildWorkInfoText` 一处没动。**（2026-10-17 三批补：链路换了腿——`navigator.clipboard` 在真应用里被主进程的 deny-all 权限钩子挡死，复制改走 `app:copyText` 由主进程代发，契约 v11；`buildWorkInfoText` 与本节的 toast 文案两处没动。别照本节旧写法把 `navigator.clipboard` 接回来，`tests/boundaries.test.ts` 会红。）**
- **导出入口只有一枚**：点它开格式弹窗（单选列表四行 + 底部「导出」，默认 CSV，打开即用、不预设记住上次选择）。四档 `xlsx / csv / json / txt` 的顺序是**表格档在前、文本档在后**。
- **列只有一张**（`EXPORT_COLUMNS`，`renderer/src/lib/history-selection.ts`）：`key` 给 json 当字段名（ASCII，给程序读），`header` 给 xlsx/csv 当首行（给人看），`CSV_HEADER` 由它派生而不是另写一份字面量。**加一列只改这一处**，三档不会互相漂——测试把「xlsx 首行 == CSV 表头」钉成一条断言。
- 各档的时间口径不同且都是对的：csv 发 `fmtCreated` 格式化串（CSV 没有日期类型），xlsx 发 `Date`（Excel 里可按时间排序筛选，这一档存在的全部理由），json 发 ISO 8601（机器读的时间不该是 locale 串）。缺项在 json 里是 `null` 不是空串——json 要能区分「没有」与「空字符串」。
- **导出 txt**：Blob + `a[download]`，文件名如 `即刻解析-历史-N条.txt`，前置 BOM（`\uFEFF`）供记事本/Excel 认 UTF-8。保存逻辑照抄首页「保存模板」那段（约 5 行）。
- **导出 CSV（Excel）**：同一条保存链路，扩展名 `.csv`、mime `text/csv`。三个 Excel 特有的坑必须处理：
  1. **BOM 是硬要求**（比 txt 更关键）：Windows Excel 打开无 BOM 的 UTF-8 CSV 会把中文显示成乱码；
  2. **RFC 4180 转义**：值里含 逗号 / 引号 / 换行 时用双引号包裹，内嵌引号翻倍（标题常含逗号，图集文件名可含换行）；
  3. **一行 = 一个作品（组）**，与 UI 行口径一致。列在 2026-10-17 从九列扩到**二十四列**（业主指令「导出的信息应该是完整信息」，见本节末「导出 = 完整作品信息」）。落地目录取 `dirOf(files[0])`（单元格里塞 N 条全路径没法看，"在哪"够用）；`bytes` 缺失的旧记录该列留空。
  - 数字失真（Excel 把长数字串转科学计数）：`作者ID` 那一列就是会撞上的列。**xlsx 与 json 不受影响**（前者是字符串单元格，读回来仍是 string；后者是 JSON 字符串），csv 档里 Excel 会把纯数字 ID 当数值显示，15 位以上掉精度 —— 这是 csv 作为「Excel 双击就能看的表」这一档的固有代价，强制成文本要把值写成 `="..."` 公式（与我们的公式注入防御同一形状，且非 Excel 的读手会看见一层壳）。**要精确复现 ID 就导 xlsx 或 json**，这条在 §4 末记下，不做预防。
  - 分隔符固定半角逗号：德语区等 Excel 本地化期望分号，属国际化问题，当前受众（中文 Windows）用逗号正确。
- **导出 xlsx（真 Excel 工作簿，2026-10-17 新增）**：走 `exceljs@4.4`，**动态 import**（全仓只有 `buildWorksXlsx()` 一处碰它，静态 import 就把 936 kB 拉进启动 chunk；实测独立 chunk 936.95 kB / gzip 270.72 kB）。三条只在这一档成立的口径：
  1. **不能挂 BOM**——它写的是字节，头前多一个字节就打不开；文本三档的 `\uFEFF` 前置是 `saveTextFile` 的事，xlsx 走 `saveBlob` 直出；
  2. **公式注入在这一档的防线与 CSV 不同**：csv 靠 `csvCell` 给 `= + - @` 开头的前置撇号，xlsx 靠「值本来就是字符串单元格」——测试把 `=HYPERLINK(...)` 读回来断言它仍是 string，谁哪天把 `cell.value` 换成公式写法就红；
  3. **首行加粗 + 冻结 + 自动筛选**：这一档存在的全部理由就是能在 Excel 里排序筛选，做不到就退回 csv。
  - **选型是业主点的**（三选一：自写最小 OOXML 零依赖 / 引 exceljs / 先不做 xlsx）——引库换来兼容性，代价是 155 个传递依赖进 lockfile 与打包链重验（`pnpm run build:app` 实跑通过）。
  - **证据分档要说清**：`tests/history-selection.test.ts` 那组是「写完再读回来」（exceljs 既是写方也是读方），证明字节自洽、字段落对格子；**真 Excel 是否认这个文件属 L5 人工**，本轮没做过。
- 取舍更新：导出拼接是纯函数（`buildWorksCsv` / `concatWorkInfo`），与首页保存模板逻辑各写一遍不抽公用（两处、行为不同——那边带固定模板文本，这边动态拼接），见 §6。

### 导出 = 完整作品信息（2026-10-17 二批，业主指令「导出的信息应该是完整信息，包作品的完整信息，如作品的发布时间，点赞，评论，收藏数等，包含作品所属的作者信息，包含作者昵称，主页链接，关注粉丝量等」）

1. **二十四列的分组顺序**：作品本身（标题/平台/类型/文件数/大小）→ 时间（发布时间/解析时间）→ 链接与落点（分享链接/落地目录）→ 作者（昵称/ID/主页/粉丝数/关注数/获赞数/投稿数）→ 互动计数（播放/弹幕/点赞/转发/评论/收藏/投币/分享）。前十六列是字面量，后八列由 `WORK_STAT_SLOTS` 展开——**加一档只改 `shared/work-stat.ts` 一处**，txt、首页结果卡徽标与表格三档同时跟上。
2. **数据必须在解析当场落盘**（三选一里他点的这条，另两条是「导出时回源补抓」与「只导当下有的」）：平台数字会涨、直链会过期，事后补不回来。所以走契约 **v10**——`HistoryEntry` 加 `publishedAt?` 与 `stat?`，写入口两侧（主进程 `parse:run`、dev mock `rememberParse`）都补，归一在 `shared/work-stat.ts`。加的是**可选字段**，旧档读进来键缺失即 undefined，不需要迁移。
3. **挑字段而不是搬对象**：内核 `ParseData` 是 passthrough 的活水，含 `data.url` / `images[]` / `qualities[].url` 三类直链，隐私红线（ARCHITECTURE §6 第 9 条）不许它们进档，`shared/history.ts` 的入参表根本不收。
4. **三套发布时间单位逐个 parser 核过**（2026-10-17）：B站 `pubdate`、抖音 `create_time`、小红书 `noteData.time`、YouTube `published` 是**秒**；Instagram `taken_at_timestamp*1000`、推特 `Date.parse(created_at)` 是**毫秒**；微博直接给 **ISO 串**。`pickPublishedAt` 因此按量级判单位（`>=1e12` 只可能是毫秒），并把超出「现在 + 一天宽限」的值判为不可信、整档不写——界面看着正常、导出的表里是三年后，这种错查不出来。
5. **计数只收纯数字**：小红书 `interactInfo` 的计数在源码里注明「可能是字符串，保留原始值交给前端格式化」，其中 `"1.2万"` 是**已经缩水**的写法，拿不回精确值。`toCount` 因此拒收它——导出是要进 Excel 求和的，近似值冒充真实值比留空更坏。
6. **老行留空**（他选「旧行留空」，不是「重算」也不是「补占位」）：v10 之前落盘的行没有这两档，csv 落空串、json 落 `null`、txt 不占行。**空 = 当时没记**，不是「零个赞」，与 §2.3「未下载」同一条口径。
7. **作者快照多带 `videoCount`（投稿）**；昵称之外的 ID/主页/粉丝/关注/获赞 本来就一直在档里，只是此前 csv / xlsx / json 一列都没写出去。
8. **界面那一行不加这两类列**（同日裁定「只在导出里，界面不加」）；表头那列因此从「创建时间」改名 **「解析时间」**——同一张导出表里两个时间并存，标签必须说得出「作品发的」与「本机记的」是两件事（详情浮层与 txt 同批跟上）。
9. **首页结果卡那排徽标改吃 `WORK_STAT_SLOTS`**：此前 `ResultCard.buildStatItems` 手抄了一份「哪个字段算播放/点赞」的映射（十二行 `push`），与导出各写各的；现在两处同一张表，作者级三档（粉丝/投稿/获赞）走 `buildAuthorSnapshot`。顺带拔掉一个 `data.stat as Record<string, number>` 的类型断言。
10. **复制正文与表格档「一套字段、两套排版」**（同日三批，业主指令「作品详情的复制按钮复制的内容字段也和导出的信息一样」）：txt 档与单行复制本来就同一个函数，缺的是**两项字段**——补 `大小` 与 `落地目录`。排版不跟随表格：八档计数仍合成一行「数据：…」、作者四项仍挂在昵称后的括号里，值继续走 `fmtCount`/`fmtBytes` 的量级缩写（粘进聊天框的文本要短）。唯一与表格档**语义不同**的一格是 `大小`：字节为 0（还没下过）时正文不写这一行——「大小：0 B」会被读成「下过但下坏了」，而 csv/xlsx 那列落 0、旁边有 `文件数 0`，读得懂。防漂交给守卫：`tests/work-info.test.ts` 逐条拿 `EXPORT_COLUMNS` 的表头去正文里找对应项（`大小(字节)`→`大小`、`作者昵称`→`作者`、`粉丝数`→`粉丝` 这几张别名在测试里显式列出），**加一列忘了同步正文 = 测试直接红**。

## 4A. 动作 D · 重新解析（2026-10-17 业主加，就是当年删掉的那条换了名字回来）

- 本页**不自己编排解析**：`reparseLinks(selectedRows)` 只交得出带分享链接的行 → App 记一条意图（`{ links, seq }`，seq 让「同一批再送一次」也能重放，否则同值 setState 不触发消费 effect）→ `setPage("home")`。
- 首页侧与 `onImportFile` 完全同一条流：`onInput(links.join("\n"))` → 600ms 自动识别 → 按 URL 去重 → 批量串行解析 → 结果卡由 `startBatch` **整表替换**（「除非重新解析了新的链接」那句口径的代码化）。所以本页一行解析代码都不新增。
- **不抄剪贴板那条「输入框非空就不覆盖」的守卫**：那条防的是被动监听吞掉手输草稿；点「重新解析」是主动命令，覆盖草稿就是这次点击的语义。
- 缺来源链接的行跳过并在 toast 里报数——历史不存媒体直链（隐私红线），没有链接就没有入口，不能猜也不能静默丢。

## 5. 边界与失败

- **选择为空**：不进入动作态（无选中根本没有动作条）。
- **导出/复制的单条**：不加前后分隔符，就是那一行信息本身。
- **删除返回**：以 `removeHistory` 的返回值为新列表（不重新 `history.list`），避免并发/竞态回读不一致。
- **删完刚好空表**：落回现有「过滤空/首次空」的空态分支，无需特判。

## 6. 与首页保存逻辑的关系

首页 `saveImportTemplate` 与本页「导出 txt」是同一段 Blob+下载。当前**只在两处、各一次调用**，直接照抄，不抽 `lib/download-text-file.ts`。抽公用模块的触发条件 = 出现**第三处**需求，或两处行为需同步修正时再抽（避免为一个当前单调用的东西造抽象）。
