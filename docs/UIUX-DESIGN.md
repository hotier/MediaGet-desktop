## 0. 设计前提：四条不可妥协的工程约束

做任何视觉决策前，先把工程边界钉死。这四条决定了哪些"漂亮方案"在本仓是**不可执行**的：

| # | 约束 | 出处 | 对设计的直接影响 |
| --- | --- | --- | --- |
| C1 | CSP `default-src 'self'`、`script-src 'self'`、`style-src 'self' 'unsafe-inline'` | `renderer/index.html:6-9` | **禁止 Web 字体（Google Fonts / CDN 字体）**。排版系统只能建立在 Windows 系统字体栈上。图标必须内联 SVG（`'self'` + `data:`），不允许 icon font / 外链 SVG |
| C2 | `img-src 'self' data: blob: https:` | 同上 | 平台封面图、头像可远程加载 —— 但必须处理加载失败与防盗链 403（现用 `referrerPolicy="no-referrer"`） |
| C3 | renderer 只能经 `window.mg` 白名单通信，`sandbox:true` + `contextIsolation:true` | `electron/main/index.ts:206-213`、`docs/ARCHITECTURE.md §1 铁律 1` | 任何新增 UI 能力若要主进程配合，**载荷形状只在 `types/ipc-contract.ts` 声明一次**（2026-10-14 单一真源改造），但通道接线仍是 4 处：`types/ipc.ts`（常量+派生类型）→ `preload/index.ts` → `main/ipc.ts`（handler）→ `renderer/lib/bridge.ts`，并由 `tests/contract.test.ts` 逐条对账。设计必须优先选择**零契约变更**的方案 |
| C4 | 依赖基线（**2026-10-14 业主第三次修订：对 UI 框架不设限**）：`package.json` runtime 依赖已含 react / react-dom / zod / electron-updater / lucide-react + `class-variance-authority` / `clsx` / `tailwind-merge` / `tw-animate-css` + 11 个 `@radix-ui/*` 原语；dev 侧 `tailwindcss@4` + `@tailwindcss/vite` | `package.json` + README「关键设计决策」 | **组件库 / 样式范式 / 动画库 / 路由一律不设限**——shadcn/ui 已按 §8 落地为渲染层基线，此前两轮修订留下的「仅允许已评审 headless 原语」白名单**作废**。仍然成立的是三条工程约束，不是审美禁令：① C1 的 CSP 禁远程字体 / 远程 SVG / icon font（技术边界，与选哪个库无关）；② 新增 runtime 依赖须与 lockfile 同 commit 提交并跑验收门；③ 换库不等于放弃语义层——色彩/密度/状态仍由 §5.2 三层 Token 描述，库的默认主题要桥进 `@theme inline`（映射表见 §8.3），组件里不许散落 hex。原为冷灰工具风写的三条审美禁令（无玻璃、单一高程、不上浮缩放）已于同日由业主解除，`tests/style-discipline.test.ts` 只剩三条工程断言 |

**结论**：本方案是"**在 437 行 CSS 上做加法**"的设计，不是"重做前端"的设计。所有 Token 都是 CSS 自定义属性，可直接替换 `:root` 块而不动一行 TSX。

## 1. 设计系统

### 1.1 风格定位

> **2026-10-14 修订**：视觉系统已整体迁移至 Air 风格（§7）。本节与 §1.3/§2 的色板、强调色、布局描述在冲突处以 §7 为准；三层 Token 架构（§1.2）与工程约束（§0）不变。

| 维度 | 决策 | 理由 |
| --- | --- | --- |
| 风格 | **克制的工程工具风**（Dark-first + Light 双轨，中性冷灰 + 单一蓝强调） | 用户是"拿来下载"的效率型用户，不是来欣赏界面的。现仓库注释已写明「克制优先：少即是多」，延续它 |
| 反风格 | 不做玻璃拟态 / 渐变营销感 / 大圆角卡片堆叠 / emoji 图标 | 下载器需要长时间停留在任务列表，视觉噪音直接降低扫读效率 |
| 视觉重心 | 把注意力预算全部给 **进度条 + 状态**，其余全部降噪 | 任务列表是产品的心脏 |
| 品牌色承接 | 保留现有 `--accent` 蓝色相（`#3b82f6` 家族），只调整明度层级 | 避免" redesign = 换色" 的常见浪费 |

### 1.2 主题架构：三层 Token

采用 **原始层（palette）→ 语义层（role）→ 组件层（component）** 三层。renderer 与主进程**只消费语义层**，永远不直接引用 `--blue-500`。

```css
/* 层 1：原始色板（唯一允许出现十六进制字面量的地方） */
:root { --blue-300:#93c5fd; --blue-400:#7cb3ff; --blue-500:#3b82f6;
         --blue-600:#2f6fed; --blue-700:#1d4ed8; /* …slate/emerald/amber/red */ }

/* 层 2：语义角色 —— 主题切换只改这一层 */
:root, [data-theme="dark"] { --bg:#0f1115; --surface:#1d2129; --text:#e6e8ee; /* … */ }
[data-theme="light"]       { --bg:#f6f7f9; --surface:#ffffff; --text:#14161a; /* … */ }

/* 层 3：组件级 —— 用 var() 组合，不引入新色值 */
.button-solid { background:var(--accent-solid); color:var(--on-accent); }
```

**为什么是这个结构**：现仓库 `:root` 里 10 个变量（`--bg/--panel/--card/--line/--text/--muted/--accent/--ok/--warn/--err`）**已经是语义层**，命名良好。本方案做的是**补齐语义层缺口**（分层表面、控件描边、语义底色、遮罩、强调文字色），并把硬编码色值下放进原始层 —— 迁移成本 ≈ 替换一个 `:root` 块。

### 1.4 字体层级

#### 1.4.1 字体族 —— 受 C1 约束，只能用系统栈

```css
--font-ui:  "Segoe UI Variable Text","Segoe UI","Microsoft YaHei UI","Microsoft YaHei",system-ui,sans-serif;
--font-num: "Segoe UI Variable Display","Segoe UI",system-ui,sans-serif; /* 数字用 tabular-nums */
--font-mono:"Cascadia Mono","Consolas","Microsoft YaHei Mono",monospace;
```

三条要点：

1. `font-variant-numeric: tabular-nums` 用于**速度 / 字节数 / 百分比** —— 现仓库这三处用比例字体，数字跳动时列宽抖动，任务列表"抖"的观感主要来自这里（`DownloadsPage.tsx:74` `${fmtBytes(t.speed)}/s`）。这是**零成本的高性价比修正**。
2. `Segoe UI Variable` 是 Win11 正典字体，Win10 自动回落 `Segoe UI`；中文回落微软雅黑。**不打包字体**（体积 + CSP 双输）。
3. 等宽只用于 Cookie 输入框（现状已如此 `.mono`）与文件路径，**不用于正文**。

#### 1.4.2 字号阶梯（8 级，含用途锁定）

| --- | --- | --- | --- |

| `--fs-body` | 14 / 1.55 | 400 | 正文默认（**保持现状 14px**，桌面工具不必 16px；WCAG 16px 下限针对移动端，min-width 820px 不适用） |

#### 1.5.1 间距（4px 基准，现状代码已隐含 4 的倍数：6/10/14/18 → 规整为 4 的倍数为准，允许 6 例外）

| `--sp-2` | 8px | 同组控件间隙（`.row` gap、`.ops` gap） |
| `--sp-3` | 12px | 卡片内块间（现 `.card` gap 8 → 12，提升可读性） |
| `--sp-4` | 16px | 卡片内边距横向（现 14 → 16）、按钮横向（现 14 → 16） |
| `--sp-5` | 20px | 页面纵向节奏、区块间隔 |

#### 1.5.2 圆角（4 档，克制）

| Token | 值 | 用途 |
| --- | --- | --- |
| `--r-sm` | 6px | chip、小按钮、徽标、输入框（现 8 → 6，控件收紧） |
| `--r-md` | 8px | 按钮、tab、封面图 |
| `--r-lg` | 12px | 卡片、弹层、banner（**保持现状**，不制造无谓 diff） |
| `--r-full` | 999px | 头像、状态点、进度条帽 |

**贴边的行底色由卡片自己裁，不给表格补圆角**（业主指令 2026-10-17「选中时候的背景色有问题，表格底部是圆角，但背景色是方角的，会溢出到表格外面」）：`Card` 是 `py-0` 且表格直接挂在它下面时，最后一行的底色会铺到卡片内缘，方角顶穿 12px 圆角——选中蓝与 hover 灰**同一条几何**，不是选中态独有的毛病。解法是给那颗 `Card` 加 `overflow-hidden`，**不要**给 `table-container` 加 `rounded-b-*`：浏览器按 padding 边裁剪、半径已自动减去 1px 边框，曲线与卡片那条天然重合；自己写圆角就是拿一个数去猜另一个数。副作用只有好处——工具栏那排方角顶穿**上**圆角的同一处毛病一起被裁掉。**只有贴边的那张卡需要它**：队列页与设置页的表格都在 `CardContent`（左右 24px 内边距 + 底部 4px）里，离角落弧线还差十几像素，加 `overflow-hidden` 纯属多余。

#### 1.5.3 阴影（暗色靠表面，Light 靠阴影 —— 不对称是有意的）

```css
/* Dark：阴影几乎不可见，层级靠 --surface 明度差 + --line */
--sh-1: 0 1px 2px #00000040;                      /* 卡片静态 */
--sh-2: 0 4px 12px #00000059;                     /* hover / 浮起 */
--sh-3: 0 12px 32px #00000073;                    /* 模态、右键菜单 */

/* Light：同层级改用低透明度冷灰投影 */
--sh-1: 0 1px 2px #14161a0f, 0 0 0 1px #e2e5ea;
--sh-2: 0 4px 12px #14161a14, 0 0 0 1px #e2e5ea;
--sh-3: 0 12px 32px #14161a1f, 0 0 0 1px #cbd2da;
```

### 1.7 图标系统

C1 约束下的可行方案有两类（**2026-10-14 业主修订：`lucide-react` 进白名单**）：**内联 SVG sprite**（`<svg><use href="#icon-x">`，同源自包含）或 **lucide-react**（tree-shaking 后按需打包，构建期同源自包含，不违反 CSP）。**仍禁止 icon font 与远程 SVG**（违反 C1）。

- 统一 24×24 viewBox，描边 1.5px，`stroke="currentColor"` —— 于是图标颜色自动跟随文字色，主题切换零维护。
- **必须成套**（自绘或选单一开源集，MIT/ISC 许可，落地时 vendored 进 `renderer/src/icons.tsx`），禁止混用两套描边风格。
- 关键图标清单（覆盖全部现有交互）：`download / pause / play / retry / cancel / folder-open / trash / more-horizontal / search / filter / check / alert-triangle / x-circle / info / moon / sun / clipboard / image / video / music / layers（图集）/ refresh（重新解析）/ keyboard`。
- **禁止用 emoji 当 UI 图标**。现状 `已保存 ✓`、`已加入队列 ✓` 用了字符勾 —— 属于文本符号不是 emoji，可保留但建议替换为 `#icon-check`（跨字体渲染不稳）。
- **2026-10-16 修订**：动效字形（侧栏四页 + 设置面五枚）改从 lucide-animated 官方 shadcn registry 逐枚拉平入仓（`renderer/src/components/ui/*.tsx`，业主定调「所有动态图标都可以用 `pnpm dlx shadcn add` 的方式导入」）——与 `lucide-react` 的静态图标同源同形，「成套」这条没破；npm 包 `lucide-animated` 试用后整体退役（整包把四百余枚图标当副作用打进 bundle，撤包实测启动 chunk 1,258→713 kB）。真源表、入仓契约与「三枚冻结」登记见 §10。

### 1.8 动效

| Token | 值 | 用途 |
| --- | --- | --- |
| `--t-fast` | 120ms / `cubic-bezier(.2,0,.38,.9)` | hover、focus、颜色过渡 |
| `--t-base` | 200ms / `cubic-bezier(.4,0,.2,1)` | tab 切换、下拉展开、toast 进出 |
| `--t-slow` | 320ms / `cubic-bezier(0,0,.2,1)` | 模态、抽屉、卡片展开 |
| `--t-progress` | 300ms linear | 进度条宽度过渡（**必须 < 200ms 节流周期的 1.5 倍**，见下） |

两条来自代码的硬约束：

1. 主进程进度事件 **200ms 节流**（`downloader.ts:67 PROGRESS_THROTTLE_MS`）。进度条 CSS 过渡设 300ms 可把 5 帧/秒的离散跳变抹成连续滑动 —— 但**绝不能超过 400ms**，否则过渡时长 > 数据间隔，进度条会"追不上"造成回缩抖动。
2. 全局必须包 `@media (prefers-reduced-motion: reduce) { *{animation-duration:.01ms!important; transition-duration:.01ms!important} }`，并且**进度条过渡在 reduce 下改为 0**（否则用户看到的是滞后的假进度）。现状 CSS 无任何 transition，加这段零风险。

**只允许 `transform` / `opacity` 做动画**（Electron 合成器友好，避免 layout 抖动）。禁止 `width/height` 动画（进度条是唯一例外 —— 它已有 `width`，改为 `transform:scaleX()` + `transform-origin:left` 可省掉重排；这是 §4 里一个明确的微优化建议）。**2026-10-16 例外**：动效字形的补间改的是 `transform` 与 SVG 呈现属性（`rotate` / `translateY` / `scaleY`·`scaleX` / `x1`·`x2` / `pathLength` / `stroke-dashoffset`）——只重绘几何、不触发布局重排，代价与 transform 同级；机制与边界登记在 §10。

#### 批量与全局操作

- 组行/单行支持多选（Ctrl+点 / Shift+点）→ 底部浮出批量条：`开始 / 暂停 / 取消 / 移除记录 / 打开全部所在目录`。
- **队列是跨重启的完整台账**（契约 v13，业主指令 2026-10-17「保留所有进过队列的数据」）：这一条**推翻了本文旧稿的两处**——① 「`snapshot()` 过滤 done，重启后完成行不再回队列（落地目录才是真源）」；② v4 的「canceled 不该每次启动回来占位」。旧稿那两句会让下一个会话把刚加回来的完成行当违规删掉，所以在此就地标注，不要照旧稿改回去。
  - 界面后果逐条对账：完成行重启后仍要有「打开所在文件夹」与「复制文件路径」，所以 `filePath`/`finishedAt` 必须跟着落盘（那两处都按 `status === "done" && filePath` 渲染，缺字段就是**整项消失**而不是报错）；失败行必须带原因，否则是一条「不知道为什么失败」的记录（旧实现 `restore()` 无条件 `error: undefined`）。
  - **done 行的直链落盘时剥成空串**（隐私红线，见 `ARCHITECTURE.md §6` 第 11 条）：队列从短命快照变成长期档之后，把带签名的 URL 永久留在盘上不合规，而到期直链对一条完成记录也没有用途。界面对应改动：右键「复制下载链接」**没有 url 就不渲染这一项**——不渲染而不是复制出一个空串。这与 §2.3 历史页「不出现需要直链的动作」同一条口径。
  - 「清理」从 v13 起才是真清理：它删的是内存 `tasks`/`order` 并立即落盘，所以清完不会重启又长回来。代价如实记一笔——档有上限，满了丢**最旧**那一批，进行中/待办并不会优先保留（数值与落盘口径在 `ARCHITECTURE.md §2` 的 store 行）。

### 2.3 历史页（`HistoryPage.tsx`）

**契约事实**：`HistoryEntry{platform,title,kind?,files[],sourceUrl?,author?,createdAt,publishedAt?,stat?}`（后两档 v10 起才有，见下面「完整作品信息」那条），存储上限 5000（`electron/main/store.ts` 的 `HISTORY_MAX`，2026-10-16 由 500 提档），接口不传 `limit` 时默认返回 200，页面「一次取满」用 `lib/local-limits.ts` 的 `HISTORY_WINDOW`。**这一页从契约 v8 起是「解析历史」而不是下载台账**（业主指令 2026-10-17，见 HANDOFF §6）：解析成功即由主进程落一行，`files` 为空数组就是「只解析没下载」——那一列在这种行上写**「未下载」**（讲状态，不写「0 个」让人以为文件被删了），详情浮层里「文件」整行收起。「下载过」的证据仍只来自落地事件，所以类型/字节/文件路径这些字段在解析行上是空的，由同作品的下载行补上：行的身份是分享链接算出的作品键（`shared/history.ts`），聚合按 `groupId` 逐字段取「组里最新那条有值的行」，所以再解析一次也不许把已下载作品的类型顶成「—」（判据在 `tests/history-works.test.ts`）。统计页只数落地行，否则「文件数」会把没下载的作品也数成一个。**不存媒体直链**是隐私红线（`ARCHITECTURE.md §3`），设计必须尊重：不出现"复制直链""重新下载"这类需要直链的动作 —— 用"**重新解析**"（把 `sourceUrl` 回填首页输入框，由内核重新走一遍）替代。`author` 是**解析那一刻**的作者快照（昵称/ID/主页/头像/粉丝·关注·获赞·投稿），2026-10-14 业主批准入档：主页与头像是公开页面，不是媒体直链；数字用快照值、不拉实时主页。**但快照口径不写在卡面上**（业主指令 2026-10-17：删掉「解析那一刻抓到的作者信息，之后不会自动更新」那句）——作者卡只摆作者本身的信息：不重复作品标题（作品信息浮层已经有），「在浏览器中打开主页」整枚按钮删掉、跳转改由**作者名本身**承担（有 `url` 才是 `<a>`，无则回落纯文本），名字/ID/平台/简介一律截断 + tooltip 预览。同一原则见 §8.4 与 2026-10-14 删隐私自述文案——**解释不常驻**。**浮层「文件」那一行同批改两条**（业主指令 2026-10-17）：① 默认只摊开第一个文件，其余折成「其余 N 个 ▾ / 收起 ▴」——`count` 可以是几十（图集），这一行不能因此把卡片顶成一片滚动区；数量不必再说第二遍，「文件数」那行已经写了「N 个」。② **路径本身就是动作**（点了即在资源管理器里定位），另挂的那枚 28px `icon-sm` 图标按钮撤掉——它正是把该行压到 45px、而其余字段全是 36.5px 的根因；行内不再有比正文行更高的东西，行高自然对齐。折叠状态**不属于作品**，换行由调用方 `key={row.key}` 重新挂载，否则上一个作品展开的几十行会跟着换过来的作品一起显示。守卫钉这三条机理（`tests/table-row-height.test.ts`）。

**多选入口在 2026-10-17 改成可见的**（业主指令，推翻 10-15 spec 里「勾选框列：不做」那一条——修饰键选择没有任何屏幕提示，实际没人找得到）：表头一枚**三态**全选框（空 / `indeterminate` / 勾）与行内那枚吃**同一条显隐规则**（业主两条指令「正常状态下隐藏多选框，鼠标浮选某一行时那一行显示，一旦选中之后其他行的多选框也变为显示」+「标题行的选中框也需要遵循这个规则，不能常驻显示」）——**常态隐藏 → 鼠标落到哪行（含表头行）哪行显 → 一旦有选中就全显**。三种状态用 `visibility` 切换而不是拿掉元素：列宽占位不变，鼠标划过不会让整张表左右抖，隐藏态也点不中（不会误选一个看不见的框）。最后那一档是这条链的关键：选中之后用户的目标是「接着挑第二行」，不该逼他逐行悬停去找框。**别给表头开特例**：我曾把这枚判成「这一列的说明兼全选入口」而留着常驻，被他否掉——常态就是整张表一颗框都不占屏。代价如实记两笔：`invisible` 把框移出 Tab 顺序，键盘侧只剩 Ctrl+A / Esc 与修饰键点选（要连键盘一起保住得改 `opacity-0` + `group-focus-within`，代价是看不见的框仍可点中）；全选入口现在要靠鼠标划过表头才发现。部分选中绝不能画成勾：画成勾，下一次点击就变成「清空」，用户以为刚才全选过。勾选框与 `Ctrl+点` 走同一个 `clickToggle`，所以点框选完接着 Shift 点仍能扩范围，一条真源。选中行的表达在 10-17 收掉一层（业主指令「选中的时候，那条记录不要有边框线条」）：**只上底色 `bg-primary/15`，不描边**——整行已经跟着底色走，再框一道等于把一行切成格子；左端那枚勾选框 + 底色足够指认「这行进了动作条」，不必再加第三种信号。这层底色贴到表格卡下缘时是方角，靠卡片自己的 `overflow-hidden` 裁进 12px 圆角（几何口径在 §1.5.2）。唯一还留描边的是**队列页跳转定位**那一下的闪烁（`outline-primary/50`，1.8 秒即退），它指认的是「这一行在这儿」，不是选择状态，别把它一起削掉。选中态与 hover **必须同色相**（业主指令 2026-10-17「多选选中的时候会有蓝色背景，但是本身鼠标浮选的时候就会有浅灰色背景，背景色会有冲突」）：kit 的 `TableRow` 自带 `hover:bg-muted/60` 那颗灰，一行同时「已选中」与「正被指着」时两种底色叠在一起就是脏色，所以**凡带主色底的行**（选中态**和**跳转闪烁那一档，同一个条件，别只判选中）把 hover 换成 `hover:bg-primary/25`——**只压暗一档、不取消 hover**：光标仍是 pointer、行仍要点得动，hover 必须有反馈，只是别换色相；未选中的行照旧吃灰。写法上没有 CSS 排序风险：`cn` 里的 tailwind-merge 认「同变体同属性」冲突，`hover:bg-primary/25` 直接把 kit 那颗 `hover:bg-muted/60` 从最终 class 串里**替换**掉（实测串里只剩一枚 hover 底色），不是靠谁写在后面赢。**动作条不占位**（业主指令 2026-10-17）：选中 ≥1 时它浮在窗口底部，工具栏保持原样（右侧那颗按钮同批撤掉，见下一段），内容为 `已选 N 项 · 导出 / 重新解析 / 移除记录 / 取消选择`——**「移除记录」不写成「删除」**，它只撤台账那一行、磁盘上的文件不动，按钮要说它做的事（与 §2.2 队列页批量条同一用词）。**动作条在 2026-10-17 收掉两枚**（业主指令「移除多选菜单的复制按钮，导出按钮合并成一个导出」）：`复制` 整枚撤掉（单行复制仍跟着作品走，在「作品信息」浮层的标题行里——撤的是批量档，不是能力）；`导出 txt` 与 `导出 CSV` 合成一枚 `导出`，**格式是导出的参数、不是两个动作**，所以它进弹窗（单选列表四行 + 底部「导出」，默认 CSV，打开即用不预设记住）。四档 = `xlsx / csv / `body`**：`main` 的 page-enter 动画带 transform + filter，会夺走 `fixed` 的 containing block，坐标就从窗口缩成内容区（实测中心偏 92px）。表格底部另垫一块与浮窗**实测等高**的空隙（`ResizeObserver` 量来的，不是写死的数）：`main` 是滚动容器，不垫高就永远压着最后一行、连它的勾选框都点不到；浮窗单行 50px、窄窗或大界面字号下折行翻倍，写死总有一天对不上。勾选框列宽 `calc(0.75rem+1rem)` 且**右内边距归零**（业主指令 2026-10-17「缩小作品列和多选框列的间距」）：原先那一列是 `calc(1.5rem+1rem)`=40px，框与作品文字之间隔着**两格** `px-3`（本列右 12 + 作品列左 12）= **导出在 2026-10-17 补成「完整作品信息」**（业主指令「导出的信息应该是完整信息，包作品的完整信息，如作品的发布时间，点赞，评论，收藏数等，包含作品所属的作者信息，包含作者昵称，主页链接，关注粉丝量等」）：表格三档从九列扩到二十四列，分组顺序是作品本身 → 时间 → 链接与落点 → 作者 → 互动计数；txt 与单行复制同批补上「数据」行与「发布时间」行，作者那行多了「关注」。三档共用的仍只有 `EXPORT_COLUMNS` 那一张表，计数八档由 `shared/work-stat.ts` 的 `WORK_STAT_SLOTS` 展开——**加一档只改 shared 一处**，txt、结果卡徽标与表格三档不会互相漂。**界面那一行不加这两类列**（同日裁定「只在导出里，界面不加」）：列表讲的是「哪个作品」，而点赞收藏是**解析那一刻的快照**（重解析才刷新），把它排进每一行会把这句话冲淡。要当场看数字有首页结果卡那排徽标，要事后看作者侧有作者卡片，作品级计数的出口就是导出。**同一张表里有两个时间且各叫各的**：`发布时间` 是作品在平台上的时刻，`解析时间` 是本机记下这条的时刻——所以表头那一列从「创建时间」改叫「解析时间」，合成一列或都叫「时间」就再也分不出「三年前发的、今天解析的」和「今天发的、今天解析的」。老记录（v10 之前写入）没有这两档 → 表格留空、txt 不占行，**留空是「当时没记」，不是「零个赞」**（与 §2.3「未下载」同一口径：缺数据不许伪装成数据）。

**工具栏右侧一颗按钮也没有**（业主指令 2026-10-17「右上角的清楚历史按钮可以移除了」，拆法他选「连通道一起拆干净」）：整表清空 = 表头全选 → 浮窗「移除记录」，走的是同一条 `history:remove`——它的 `keys` 上限 5000 就是 `HISTORY_MAX`，一次点得掉整张表，能力没丢，丢的只是第二条入口。所以 `history:clear` 通道、主进程 handler、preload 白名单、bridge/mock 与 `store.clearHistory()` 一并删除，`CONTRACT_VERSION` 8→9：**通道集合变了就升号**（存档形状没变、清空与移除落到的结果本来一样，旧档不需要迁移），与 v5/v7 同一条理由。留着一条零调用方的通道不会编译报错，只会变成下一个读契约的人多出来的一个「该怎么用」。

| 直链时效 | **不拿时间改按钮语义**（业主质疑「你确定有效期只有 5 分钟吗」后实测：抖音播放链整串查询里没有任何时刻，封面图签名约 14 天——「分钟级」只是各家 CDN 的经验下限，不可验证的数就不许当判据）。UI 只报事实：底部元数据行 `解析于 HH:mm:ss`，超过 5 分钟再补一句「链可能已过期，下载会自动重新取链」，主按钮始终是 `[下载 N 项]`。真过期在失败之后处理：403 → 主进程按作品键续链并**只重跑一次**（`electron/main/link-renew.ts`），队列那一行用 info 图标承载 `note`（沿革见 `UIUX-HANDOFF.md` §6 的契约 v12 那条） |
| 同一链接重复解析 | 内核 24h LRU 缓存（`core-adapter/cache.ts`）→ `durationMs` 会突然变成 1ms。UI **必须**在此时显示 `缓存命中` chip，否则"1ms 解析成功"看起来像假的 |
| 重复入队 | `downloader.ts:211-247` 有 `claimedTargets` 避让逻辑（同目标活任务防双写）。UI 应显式提示「该文件已在队列中」而不是静默加一条看不见的重复 |

### 3.3 系统托盘与窗口行为（**当前完全不存在 —— 本方案最重要的一处补全**）

**事实核查**：全仓 grep `Tray` / `Menu.` / `globalShortcut` / `nativeTheme` → **零命中**。且 `main/index.ts:258-261`：

```
app.on("window-all-closed", () => { store.flush(); if (process.platform !== "darwin") app.quit(); })
```

**后果（可直接复现的产品缺陷）**：Windows 上点 ✕ → **整个应用退出** → 正在下载的任务被切断。README/ARCHITECTURE 的 P2 验收是「重启后队列/历史完整」，`.part` 续传确实能救回来，但**用户心智里"关闭窗口 = 最小化到托盘"（所有国内下载器的惯例）**。当前行为等于：**用户只是想收起窗口，却杀掉了 12 个下载**。这是比任何配色都严重的问题。

| --- | --- |

### 3.6 隐私与"如实呈现"规范（本项目的品牌性格）

代码注释里反复出现"如实"二字（README「功能特性」的「结果来源如实标注」、`types/ipc-contract.ts:292`「降级可见 —— 不假装有防护」、`index.ts:71`「启动期如实汇报完整性档位」）。这是这个产品最稀缺的设计资产，**UI 必须把它当视觉语言来强化，而不是抹平**：

1. 任何"降级/回落/mock/未校验"状态**不得只显示一个绿点**。三态色 + 文字 + 可展开原因。
2. 二进制完整性四态（`verified/degraded/rejected/missing`）在**首页**也应有一处低干扰的存在感（如结果卡底部 `via` 行出现「TikTok 需 ffmpeg · 当前未校验 ⓘ」），因为它是解析失败的潜在根因。
3. Cookie 一律掩码 `***`（现状正确 ✅），UI 永不明文回显、不进历史、不进"复制诊断信息"。
4. 「复制诊断信息」内容需白名单：版本号、Electron 版本、内核模式、failType、耗时 —— **不含** Cookie、不含完整文件路径（可含目录名）、不含用户链接。
5. 隐私承诺在空态/关于页用一句人话讲清（现状 `ParsePage.tsx:113` 那句已经很好，保留并强化）。

### 4.2 契约变更的标准动作清单（每次改动照抄）

```
1) types/ipc-contract.ts   —— 形状唯一声明处：改/加 schema，并在 CONTRACT（invoke）或 EVENTS（事件）登记该通道
2) types/ipc.ts            —— 加 channel 进 IPC 常量表（禁散落字面量）；类型是 z.infer 派生，一般无需改
3) electron/main/ipc.ts    —— handler 里 wrap(IPC.xxx, XxxSchema, …)；入参自动校验，dev 下出参自动校验
4) electron/preload/index.ts —— 白名单加一行，返回解绑函数（事件类）
5) renderer/src/lib/bridge.ts —— 类型化封装 + unwrap
6) tests/contract.test.ts / boot.test.ts —— 契约对账（漏登记即红）；tests/ipc.test.ts 端到端断言新字段
7) 旧档兼容：userData/config.json 缺新字段 → loadConfig() 的 { ...DEFAULT_SETTINGS, ...raw.settings } 已兜底 ✅（store.ts:95-101）
```

⚠️ 三个易踩的坑（读码所得）：

- `SettingsPatchSchema` 是 **`.strict()`**（`types/ipc-contract.ts:176`）→ renderer 传任何未声明字段直接 `bad-input`。P2 加 `theme` 必须先加 schema。
- `settings:set` 传**全量** `AppSettings`（`SettingsPage.tsx:38-42` 现状 `...current`）→ 新字段若漏进 `current` 会被 strict 拒。
- Cookie 掩码约定：`"***"` = 不修改、`""` = 清除（`electron/main/ipc.ts:217`）。任何"清空 Cookie"的新按钮必须**发空串**，不能不发。

### 7.2 色板与魔法色协议

- **高对比黑白灰基座**（Token 层 1，`styles.css`）：底色 `#121212`、卡片 `#1E1E1E`、主文字 `#F2F2F2`（非纯白）、次要 `#B3B3B3`；light 覆盖 `#F2F2F3/#FBFBFC/#1A1A1C`。静态强调一律灰（`--air-accent-fallback #D4D4D4`），色彩只经动态魔法色进入。
- **动态魔法色**（`renderer/src/lib/accent.ts`）：当前封面 → canvas 32×32 降采样 → 每通道 32 级量化直方图、权重 =1+3×饱和度（死黑/过曝像素剔除）→ 主色 HSL 亮度钳位 L∈[0.45,0.75] → 写 `documentElement` 的 `--accent-color`；`@property --accent-color`（syntax `<color>`, inherits true）+ **只在 `:root` 声明** 400ms `cubic-bezier(0.4,0,0.2,1)` 过渡（写在 `*` 会覆盖组件自身 transition 简写）；`--accent-ink` 按相对亮度翻转（>0.5→`--air-on-accent-dark`，否则 light）。提取失败/跨域污染画布 = 移除内联覆盖回落缺省灰。**JS 内不写 hex 字面量**（色值只活在层 1）。
- 派生角色全走 `color-mix`：`--accent-soft 18%`、`--tint-info 12%`、`--line-focus/--accent-solid/--progress-fill = --accent-color`。消费点：选中竖条（侧栏 3px）、进度条填充、主按钮填充、聚焦描边。（`--accent-glow 30%` 随底部任务条一并移除 —— 它唯一的消费点是底条光晕。）

- 高程恢复为两级：卡片 `shadow-sm` + 浮层 `shadow-pop`（`--sh-pop`），描边仍在（Windows 上纯阴影不稳）。

  `--overlay` 不删——结果卡「+N」角标压的是**图**不是页面，两档不共用。
  玻璃只作为遮罩与浮层的轻度处理，界面主体仍是实心面板。

  `sheet` 仍 `data-state=open`，而卡片没开时点页面照样关浮层（回归不坏）。
  进出对称（同轮指令「收起也应该有向下收起的动画」）：用法处加 `slide-in-from-bottom-8` +
  `data-[state=closed]:slide-out-to-bottom-8`（±2rem）；
  tw-animate-css 的 `enter/exit` 关键帧写 `transform`，与居中用的 `translate` 属性（`-translate-x/y-1/2`）是两个属性，
  叠加不冲突 —— 实测 `translate: -50% -50%` 与 `transform: translate3d(0,32px,0) scale(.95)` 同时成立，中心不偏。
  收起动画看得见的前提是**内容不能被先抽空**：可见态与数据态分两个 state（`authorShown` 关掉、`authorRow` 留着），
  否则整段退场里浮层已是空壳。

  （进入快收尾、退场起步慢，退场拉长到 250ms）。实测新曲线 `cubic-bezier(0.4,0,1,1)` 0.25s：

| 单文件体积分布、常看作者 | 历史明细里**已落地的行**（`isLanded`，即 `files.length > 0`；`history:list` 取满 `HISTORY_WINDOW = 5000`，见 `lib/local-limits.ts` 单一来源） | 逐文件粒度与作者名只有明细给得出；计数档故意不带文件名与作者（ARCHITECTURE §6 第 8 条）。v8 起明细档是**解析**历史，没下载的作品也占一行，这两张卡算的是「文件」，所以先过滤再统计 —— 卡片口径没变，变的是档里多了不算文件的行。 |

版面按「先结论后分布」，且**默认这一页只有图**：页头一行五个读数（成功率 / 累计字节 / 平均速度 / 解析次数 / 计数起点，「刷新」在这一行右侧）→ 趋势全宽 → 平台/类型（xl 双列）→ 体积/解析（xl 双列）→ 活跃热力 → 常看作者。原先那张「累计」纯文本卡（9 行读数）压成了页头一行 —— 业主指令「默认只显示统计图」；被压掉的五个读数（下载成功、失败、取消、平均耗时、解析成功率）不再单列，失败与取消回到趋势图的失败折线与 tooltip。「刷新」一次读两源（`Promise.all`），**不做每卡独立刷新**：两本账要同一时刻才有可比性，且统计页不在热路径上。

### 9.2 图表底座：裸 ECharts + 本地四件（业主选定方案 A）

评估过 `@devstool/shadcn-echarts`，结论是包装层的三个卖点在本仓全都失灵，2026-10-16 业主选 A：直接依赖 `echarts@6`，本仓写薄适配器。

1. **自动上色失灵**：它按 shadcn 惯例读 `.dark` 类判明暗，本仓是反向约定（`:root` 即暗，明暗走 `data-theme`、风格走 `data-style`）；且 token 是三层链，自定义属性的 computed value 只做 `var()` 替换、**不求值 `color-mix()`** —— 拿那串文本喂 canvas 解析不了。
2. **体积要自己控**：`echarts/core` + 显式 `use([...])` 只注册用到的（Bar/Line/Heatmap + Grid/Tooltip/Legend/MarkLine/VisualMap + CanvasRenderer，另加一个 `echarts/features` 的 `LegacyGridContainLabel` —— v6 把 `grid.containLabel` 挪进 opt-in 兼容件，漏登记**不报错**、只把类目名静默裁掉，真窗口实测踩过）。本机实测：全量 1.10 MB / gzip 370 KB / Node eval 106 ms → 摇树 625 KB / eval 48 ms。再加整页 `React.lazy`，`vite build` 产物实测 **StatsPage chunk 619.55 kB / gzip 210.42 kB**，启动 chunk **712.62 kB / gzip 227.62 kB**（较统计页上线时 513.2 kB 的增量主要是 §10 图标动效栈：`motion` + 九枚入仓字形）里 echarts 标记命中 **0 次** —— 不开统计页就一行 echarts 代码都不下载。
3. **口径不许外包**：本仓的作图规矩（§9.3）恰恰长在 tooltip 内容与配色语义上，那些正是包装层替我决定的部分。

`renderer/src/components/charts/` 四件各守一层，越界的都不写：
- `echarts-core.ts` —— 唯一注册点。加一类图就在此加一行 `use`，别处不许 import `echarts`。
- `palette.ts` —— `useChartPalette()`：把 utility class 挂到离屏探针元素上读 `getComputedStyle` 的 `rgb()`，**代码里一个色值都不写**（§1.2「层 1 是唯一 hex 处」在 canvas 侧没有破口）。`MutationObserver` 盯 `:root` 的 `class/style/data-theme/data-style` 四个属性，于是明暗、五套风格、界面字号、界面字体改完图表实时跟上，不必给 `theme.ts` 加通知口子。色阶用 `withAlpha(primary, 0.16…1)` 叠出来，不再引入一套 ramp token。
- `options.ts` —— 纯 option 构造（`trendOption` / `rankOption` / `heatOption` / `histogramOption` / `rankHeight`）：palette 由调用方注入、不碰 DOM，所以「失败次数落没落在右轴」「条长是份额还是实际数」这类判定能在 node 环境整份测掉（30 例），不必为验证一个数字去起 canvas。tooltip/label 回调只取 `dataIndex` 回自己的数组拿数，**不读 `params.value`**（那是 ECharts 加工过的显示值，再格式化一次就把口径绕回悬浮层）。
- `EChart.tsx` —— 哑宿主：`init` / `setOption(option, { notMerge: true })`（合并会把上一次的系列留成残影）/ ResizeObserver / dispose / `onSelect(dataIndex)`。零业务逻辑，所以它不需要测试替身。

热力图的色阶走 `visualMap: { show: false }` —— 只借它的数值→色阶换算，不卖它的滑块控件。

### 9.3 三条作图规矩

1. **数值常显**：榜单条右固定显示「实际数 · 份额」，直方图柱顶显示份额，卡片标题右边显示该图合计；只有趋势图例外（365 根柱贴不下 365 个数，合计写在标题右边）。进度条、环形图一个都没有。
2. **坐标轴不是信息载体**：榜单的数值轴整条隐藏、上界锁 1 —— 长度已经表达了份额，刻度只会重复一遍（所以第一名满格是错的，份额 63% 就只画 63%）。趋势图的轴留着，因为「哪天破了 20 次」要能对着刻度读；`minInterval: 1` 是硬要求 —— 「1.5 次下载」的刻度等于把数据讲坏，而字节档撤掉该约束（整数语义在那儿不成立）。
3. **除零不猜**：分母为 0 的比率是 `null` → 页面渲染「—」，不写 0%（「0% 成功率」和「一条都没下过」在图上是同一个形状，前者是结论，后者是不知道）；全零热力的 `visualMap.max` 顶到 1，否则 0/0 让色阶塌成一片；空榜单 `series` 给空数组，不画一根 0 长的条。平均速度的分子用 `totals.elapsedBytes`（有耗时样本的那部分字节）而不是 `totals.bytes` —— 两条总线相除造出一个偏高的假速度且无从发现；`sampled === 0` 时页面说明「需要至少一条带耗时的完成记录，老记录不追溯补这维度」。

### 9.4 交互：可交互 = 换口径，不是缩放与拖拽

- 趋势两组按钮：窗口 `7 / 30 / 90 / 365` 天 + 口径 `次数 / 字节`。字节档换的是柱子的数据、轴标签格式化与刻度约束，失败折线不动。
- 榜单口径 `次数 / 字节 / 失败 / 解析` **一组按钮同时驱动平台榜与类型榜**：两榜同口径才能横向对照，分开切会造出「平台按失败排、类型按字节排」这种不相干的两句。
- **点平台榜一行 → 历史页只看这个平台**：App 层传 `platformFocus = { key, seq }`（`seq` 让重复点同平台可重触发，与剪贴板填入同一条手法），历史页收到即落筛选。跨页只传平台键，不传行 id。
- 本机占用不在这一页：六桶扫描结果与清理动作都在设置「通用」的缓存卡，统计页只摆上面两本账（2026-10-16 业主指令把这张卡从本页摘掉，占用是「当下快照」、与累计/明细不同一条时间轴，摆在一页里容易被读成第三本账）。
- 悬浮层只做补充，不做唯一出口：趋势 tooltip 列「下载 / 字节 / 失败 / 解析」四项，榜单 tooltip 给失败率或作品数，热力给「周三 21:00 · 12 次」。
- 键盘与读屏：图是冗余呈现，非图出口是页头那一行五个读数 + 各卡标题右边的合计（`EChart` 各带 `ariaLabel`，如「近 30 天逐日下载与失败趋势」）。压掉累计卡之后，失败与取消次数在这页只剩趋势的失败折线与逐日 tooltip，成功率仍在页头。

### 9.5 四态与验收边界

- 加载：快照未到 → 三枚 `Skeleton`（28 / 56 / 44 高，占住大致版面）。
- 空态：`isEmptyStats`（下载 + 失败 + 解析三者为 0）→ 居中 `ScanSearch` 引导「还没有可统计的记录 / 计数从安装这一刻起算」+ 重新读取按钮。单张卡的档没记录用行内一句「这一档还没有记录」，不整页打空。
- 错误：两源任一失败 → 顶部 destructive Alert 说清哪本读不出来，已到的数据照常渲染（不整页变白）。
- 已验：`tests/stats-aggregation.test.ts`（18 例，聚合口径）+ `tests/stats-options.test.ts`（33 例：option 构造、取色换算、`fmtPercent`·`fmtDuration`·`fmtSpeed` 三个格式化出口，另三条目录纪律 —— echarts 只在登记点 import、`LegacyGridContainLabel` 在列、charts 目录内不写 hex）；四门绿；chunk 切分按 §9.2 实测数字核对（启动面不含 echarts）。
- 已验（一次桌面级核对，dev 预览页 + mock 桥）：七张图全部挂载（`_echarts_instance_` 齐备、canvas 尺寸 = CSS 尺寸 × dpr 1.25）；喂进 canvas 的色确实是探针取回的 token 值（primary `rgb(37,99,235)`、bg-sunken `rgb(233,235,238)`、err `rgb(192,57,47)`、muted `rgb(89,96,106)`）；把 `data-theme` 从 light 翻到 dark，热力图主色随之从 `89,96,106` 变 `154,160,167` 再翻回 —— MutationObserver 那条路是活的；控制台无 warn。

### 10.1 入仓契约 + npm 包退役

**入仓组件形状（九枚同构）**：`"use client"` 头；外壳 `div` 承接 `className`（styles.css 的 `.anim-icon svg` 笔重规则依赖这一层——组件把 `stroke-width="2"` 硬编码为呈现属性，CSS 把它压回全站 1.5）；内为 `svg`（`stroke=currentColor`、24 视窗、尺寸走 `size`，这里传 16）；`forwardRef` 出 `{ startAnimation, stopAnimation }`——**挂上 ref 后组件自身不再响应 hover、触发权归调用方**（导航与设置页分类走 `components/AnimIcon`：成为当前项那一下 start、离开那一下 stop；设置钮是裸用 + 悬停驱动，见 App）。

**stop 是快速平滑归位（0.15s 短补间）、不是整段回放、也不是瞬跳**：归位契约经三稿收敛——registry 原版 `stopAnimation` 是 `start("normal")` 整段回放式归位，History 的时针 -360°→0° 会可见地回转一整圈（业主 2026-10-16 真窗口报「点其他图标时 history 仍有一段动画」）；v2 改为瞬停（`controls.stop()` + `controls.set("normal")`）又被报「更生硬」；v3 定稿九枚统一 `controls.start("normal", { duration: 0.15, ease: "easeOut" })`——不播整段回程、也不瞬跳。唯一例外是 **History 的时针**（-360° 整圈回转 ≡ 0°，任何补间都会重演整圈回转）：独立一副 controls 瞬时写回，指针与分针走短补间；cpu 快照的 `normal` 另补了 `scaleY`/`scaleX`（归位若停在引脚伸缩半途会把引脚冻结在拉伸态）。`tests/nav-icons.test.ts` 有 10 条守卫防 registry 重新拉取覆盖修复。复位本身仍不可省：单值变体（History 的指针、Download 的箭头）落定后不回原位，不复位则二次激活时 start 的目标 == 当前值，动效静默失效（本机实测坐实）。系统「减弱动态效果」开着则整个跳过——动效是 JS 补间，§1.8 第 2 条的 CSS 规则管不到它（`useReducedMotion` 在 AnimIcon 与设置钮悬停驱动两处各拦一次）。

**npm 包 `lucide-animated` 试用后退役**，三个死因：① 整包四百余枚图标当副作用打进 bundle（顶层 forwardRef 无 PURE 标注、无 sideEffects 声明），撤包实测启动 chunk **1,258.17 kB / gzip 283.01 → 712.62 kB / gzip 227.62**；② 包内缺 palette；③ 三枚字形停在旧画法（入仓版同样冻结，那是快照时点，见 10.2）。morphicons 时期试用的 `morphicons@2.0.0`、`lucide@1.57.0`（及 `pnpm-workspace.yaml` 两条对应 `minimumReleaseAgeExclude`）一并退役；**动效栈留下的 runtime 依赖只有 `motion@14.2.0`**（入仓组件从 `motion/react` import 的补间引擎）。`lucide-react@1.57.0` 照旧服务全站静态图标。

### 10.2 漂移闸与「已知冻结」

`tests/nav-icons.test.ts`（25 例）把入仓快照与 `lucide-react` 对照字形各自渲染成静态 SVG、抽线段/弧块/圆/矩形整块多重集比对（定点两位小数后比；morphicons 时期深路径读 `__iconData` 的写法已退场；受控停守卫 10 例见 10.1、10.4）：

- **登记内的同类差异不算漂移**：元素拆分（下载箭头 polyline+line vs 规范化 path，历史指针拆两段各绕 (12,12) 转）与浮点噪声（`5.999` vs `6`）。
- **三枚已知冻结**：settings 直齿（`M12.22 2h`，2 元素）、sliders-horizontal 导轨 y=4·12·20（9 元素）、cpu 8 针 + 6×6 内芯（10 元素）——registry 快照停在旧版 lucide 画法，与 `lucide-react` 现版（圆齿 / y=5·12·19 / 12 针）不同形。逐枚断言「**仍**不同形 + 图元数 + 画法指纹」，上游哪天追平或再变都会红，回来重新登记。
- **palette 是 vendored 重绘**：轮廓为描边画线动画反向重绘、依赖 `stroke-dasharray="70"`，四枚圆点与 lucide-react 逐点一致——按「圆点集合相等 + 整体不同形 + dasharray 在」钉住。
- **外壳契约**单独成例：currentColor 描边 / 无填充 / 24 视窗 / size 生效 / className 落在外壳 div；`SETTINGS_GLYPHS.categories` 键集合 = 设置页五个一级分类。

### 10.3 动效边界（§1.8 的例外登记处）

- **改的是 `transform` 与 SVG 呈现属性**（`rotate` / `translateY` / `scaleY`·`scaleX` / `x1`·`x2` / `pathLength` / `stroke-dashoffset`，另加 opacity）——只重绘几何、不触发布局重排，代价与 transform 同级；§1.8 的例外即为此开。
- **设置钮（悬停驱动）与设置页分类（激活驱动）都参与**；设置页分类还带「挂载即播」——进设置页本身就是一次切换，定位到的那枚要播一次（`AnimIcon` 的 `animateOnMount`；业主同日报「点击设置转到设置页时定位到的那个图标没有动画」）。唯一不参与的是更新按钮——它根本不是动效字形（lucide-react 静态图标），出现/消失也是挂载/卸载（如实记账）。
- **无障碍**：图标不传 `label`（同一行已有可见文字，同一句话不念两遍）→ 自动 `aria-hidden="true"`；选中态的对外出口仍是 `aria-current="page"`（侧栏与设置页分类选中样式都走它）。
- **成本**：启动 chunk 713.28 kB / gzip 227.74 kB（含九枚字形与 motion；v3 归位契约后实测 +0.66 kB / gzip +0.12 kB，来自归位字面量与 cpu 变体补键）；CSS 55.31 kB / gzip 10.66 kB；产物内 lucide-animated 包体标记命中 0 次（死重清零）。

### 10.4 验收边界

- **已验（静态几何）**：`tests/nav-icons.test.ts` 25 例全绿（导航四枚逐段同形、三枚冻结指纹、palette 圆点对拍、外壳契约，另加 10 条「受控停 = 0.15s 短补间归位」的 vendored 偏差守卫，含 history 时针例外）；四门全绿（typecheck / lint / 684 例 / `verify:binaries:release`）；chunk 数字为上表实测。
