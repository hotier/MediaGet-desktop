# 历史页多选 · 删除与复制/导出 · 设计

日期：2026-10-15　状态：业主已认可（含本轮去掉「重新下载」）

## 目标

历史页列表当前只能逐行操作（点行开详情）或整体「清空历史」。多选补上中间缺口：
挑出若干条，**删除**它们（不全清）或**复制/导出**它们的作品信息。

## 明确不做（非目标）

- **重新下载**：曾纳入，业主指令删除。它是唯一需要串行解析编排的部分，去掉后功能收敛为「批量删 + 批量导出信息」，很薄。
- **在文件夹中定位**（原 D）：不做。
- **勾选框列**：不做。修饰键模式下高亮即「已选」，不额外占一列、不加常驻 checkbox。
- **CSV 导出**：~~不做~~ → **业主要求后纳入（2026-10-15 修订）**：txt + CSV 双格式，CSV 面向 Excel。
- **jsdom / DOM 交互测试**：不引。仓库 test 依赖只保留 vitest（见 docs/TESTING.md §6）。

## 1. 选择模型

- **行键 = `groupId ?? id`**：一行可能聚了图集多文件，选中＝选中整组（一个 groupId）。
- **点行（无修饰）**：照旧打开底部详情 Sheet，行为不变。
- **Ctrl / ⌘ + 点**：切换该行选中态，且**不**开详情。
- **Shift + 点**：从「上一个被点的锚点」到当前行，按**当前可见行序**连续选中（范围含端点）。锚点取最近一次非-Shift 点选的行。
- **Ctrl / ⌘ + A**：**替换**当前选择为「可见全部行」（不是并入已有选择）。理由：全选是「我就要操作这些可见的」，若并入会把此前选中、但已被筛掉的行一起带进操作——与"我看到的=我要操作的"直觉相反。已筛掉的行仍可被删除/导出，但需经 Shift 范围或此前手动选中，不由 Ctrl+A 带入。
- **Esc**：有选中时清空选择；清空动作优先于本页其它 Esc 处理。
- **筛选时选择保留**：选中后再筛掉某行，该行仍在选择集合内（与 Windows 资源管理器一致）。动作条计数「已选 N 项」按选择集合大小，不按可见数。
- **视觉**：选中行复用现有高亮（`bg-primary/15` + 描边），不新增样式体系。

## 2. 工具栏

- 无选中：右侧维持现状的「清空历史」。
- 有选中：「清空历史」临时替换为动作条 —— `已选 N 项 · [复制] [导出 txt] [删除] · [取消选择]`。
- 「删除」用 destructive 变体；「取消选择」把选择集合清空、动作条收回。

## 3. 动作 A · 删除选中（唯一动主进程的）

- 主进程新增 `store.removeHistory(ids)`：按**条目 id** 过滤后落盘，**返回剩余列表**（UI 直接 `setList(剩余)`，省一次回读）。
  - 传入的是行键集合（`groupId ?? id`）；主进程删除口径：命中「条目 id ∈ ids **或** `条目.groupId ∈ ids`」的全部记录——保证删整组。
- 契约新增通道 `history:remove { ids: string[] } → HistoryEntry[]`，在 `types/ipc-contract.ts` 的 `CONTRACT` 登记，`types/ipc.ts` 出 `IPC.historyRemove` 常量与派生类型；`contract.test.ts` 自动对账（漏登记即红）。
- 删除后清空选择集合，动作条收回。
- **只删记录，绝不碰磁盘文件**——与「清空历史」同口径（历史本就只存路径字符串，不存内容）。
- 二次确认：弹 Dialog（destructive），复用现有「清空历史」确认弹窗的形制；确认后执行。

## 4. 动作 C · 复制 / 导出（零 IPC，纯前端）

- 每条选中行复用 `buildWorkInfoText`（renderer/src/lib/work-info.ts）生成正文。
- 多条拼接：以一行分隔 `———`（全角破折号成串，可读、不与正文里的破折号项混淆）连接各条。
- **复制**：整段进 `navigator.clipboard.writeText`，成功 toast「已复制 N 条」，失败 toast「复制失败」（与现有复制作品信息一致，走 sonner）。
- **导出 txt**：Blob + `a[download]`，文件名如 `即刻解析-历史-N条.txt`，前置 BOM（`\uFEFF`）供记事本/Excel 认 UTF-8。保存逻辑照抄首页「保存模板」那段（约 5 行）。
- **导出 CSV（Excel）**：同一条保存链路，扩展名 `.csv`、mime `text/csv`。三个 Excel 特有的坑必须处理：
  1. **BOM 是硬要求**（比 txt 更关键）：Windows Excel 打开无 BOM 的 UTF-8 CSV 会把中文显示成乱码；
  2. **RFC 4180 转义**：值里含 逗号 / 引号 / 换行 时用双引号包裹，内嵌引号翻倍（标题常含逗号，图集文件名可含换行）；
  3. **一行 = 一个作品（组）**，与 UI 行口径一致：`标题,作者,平台,类型,文件数,大小,创建时间,分享链接,落地目录`。落地目录取 `dirOf(files[0])`（单元格里塞 N 条全路径没法看，"在哪"够用）；`bytes` 缺失的旧记录该列留空。
  - 数字失真（Excel 把长数字串转科学计数）**本轮不预防**：本表没有 ID 类长数字列，文件数本来就该是数字；若将来加作者 ID 列，需强制文本（`="..."`），届时再说。
  - 分隔符固定半角逗号：德语区等 Excel 本地化期望分号，属国际化问题，当前受众（中文 Windows）用逗号正确。
- 取舍更新：导出拼接是纯函数（`buildWorksCsv` / `concatWorkInfo`），与首页保存模板逻辑各写一遍不抽公用（两处、行为不同——那边带固定模板文本，这边动态拼接），见 §6。

## 5. 边界与失败

- **选择为空**：不进入动作态（无选中根本没有动作条）。
- **导出/复制的单条**：不加前后分隔符，就是那一行信息本身。
- **删除返回**：以 `removeHistory` 的返回值为新列表（不重新 `history.list`），避免并发/竞态回读不一致。
- **删完刚好空表**：落回现有「过滤空/首次空」的空态分支，无需特判。

## 6. 与首页保存逻辑的关系

首页 `saveImportTemplate` 与本页「导出 txt」是同一段 Blob+下载。当前**只在两处、各一次调用**，直接照抄，不抽 `lib/download-text-file.ts`。抽公用模块的触发条件 = 出现**第三处**需求，或两处行为需同步修正时再抽（避免为一个当前单调用的东西造抽象）。
